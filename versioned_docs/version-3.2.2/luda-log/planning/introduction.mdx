# Luda Log 프리뷰

## 프로젝트 개요


Luda Log는 단순히 프로젝트 결과물을 나열하는 포트폴리오 사이트가 아닙니다.

기존에는 노션 및 깃허브 블로그를 활용하여 프로젝트를 정리하고 있었습니다.

노션은 각각의 프로젝트를 설명하고 기록하는 데에는 큰 장점이 있었고,
깃허브 블로그나 레포지토리 내부의 docs 문서와 함께 사용할 때에도 좋은 시너지가 있었습니다.

특히 프로젝트를 상태별로 분리하고,
운영 기록과 구조를 함께 관리할 수 있다는 점은 매우 매력적이었습니다.

하지만 실제로 사용하면서 몇 가지 한계를 느끼게 되었습니다.

노션은 계층형 문서를 지원하지만,
동시에 완전한 구조형 문서 시스템이라고 보기도 어려운 독특한 탐색 방식을 가지고 있습니다.

그 결과:

- 프로젝트 규모가 커질수록 탐색 흐름이 복잡해지고
- 문서 간 관계를 직관적으로 파악하기 어려워졌으며
- 단순히 읽는 것 자체에도 러닝 커브가 생기기 시작했습니다.

사람인이나 잡코리아의 이력서는 지나치게 성과 중심이며,
깃허브나 기술 블로그는 문제 해결과 구현 과정 중심의 기록에 가까웠습니다.

노션은 이 두 성향의 중간 지점에 가까웠지만,
결국 플랫폼 자체의 구조 안에서 문서를 구성해야 한다는 한계가 존재했습니다.

실제로 최근 면접을 다녀온 한 회사의 대표님께서는,
이력서를 읽으며 인간 박이나에 대한 호기심은 생기지만
그 사람 자체를 충분히 설명해주지는 못하는 것 같다는 말씀을 해주셨습니다.

특히 저는 단순 결과물이 아니라:

- 왜 이런 구조를 선택했는가
- 어떤 운영 경험이 있었는가
- 어떤 고민 끝에 구현 방향이 결정되었는가

를 함께 기록하고 싶었습니다.

그래서 단순 블로그 대신,
제 색깔과 구조를 직접 담아낼 수 있는 웹사이트를 만들기로 결정했습니다.

기존 깃허브 블로그가
트러블슈팅과 기술적인 문제 해결 중심의 기록이라면,

Luda Log는 보다 상호작용적인 형태의 archive를 목표로 하고 있습니다.

서울예술대학교 재학 시절 접했던 p5.js와 인터랙티브 작업 경험들을 바탕으로,
단순히 읽는 문서가 아니라
사용자가 직접 탐색하고 반응하는 형태의 개발 아카이브를 만들고 싶었습니다.

## 핵심 방향성

Luda Log는 다음과 같은 방향을 중심으로 설계되었다.

### 기록 중심 구조

프로젝트를 단순 게시글처럼 나열하는 대신,
하나의 운영 기록과 manuscript처럼 읽히도록 구성한다.

단순 기능 소개보다:

- 왜 이런 구조를 선택했는가
- 어떤 문제를 해결하려 했는가
- 어떤 운영 경험이 있었는가

를 중심으로 기록한다.

---

### Archive Experience

사이트 전체는 일반 블로그보다
하나의 archive room 혹은 manuscript archive처럼 보이는 것을 목표로 한다.

이를 위해:

- dark archive aesthetic
- runtime UI
- manuscript viewer
- workspace explorer
- tarot reconstruction

등의 구조를 도입하였다.

단순한 정보 탐색보다
기록을 열람하고 해석하는 경험에 가까운 방향을 지향한다.

---

### Runtime 기반 UI

Luda Log의 일부 영역은
단순 document viewer가 아니라
실행중인 runtime process처럼 동작하도록 설계하였다.

특히:

- PROJECT LOG
- DEV LOG
- Workspace Runtime

등은 일반 markdown viewer 대신
runtime terminal과 process window를 참고하여 구성하였다.

이를 통해 단순히 문서를 읽는 것이 아니라,
실행중인 시스템 내부를 탐색하는 느낌을 만들고자 했다.

---

## 기술 스택 선정 이유

### Docusaurus

Luda Log는 Docusaurus 기반으로 구축되었다.

선정 이유는 다음과 같다.

- markdown 기반 문서 관리
- versioning 지원
- category 기반 archive 구조
- 정적 배포 환경
- 유지보수 편의성

특히 versioning 기능은
단순 문서 버전 관리가 아니라
운영 기록의 스냅샷을 보존하는 방향으로 활용하고 있다.

---

### React 기반 구조

Docusaurus는 React 기반으로 동작하기 때문에:

- runtime UI
- workspace interaction
- animated overlay
- custom archive component

등을 자유롭게 확장할 수 있었다.

기본 문서 시스템 위에
하나의 archive runtime을 구축하는 방향으로 활용하고 있다.

---

## 주요 구성 요소

### Archive Room

프로젝트와 기록들을 archive 형태로 탐색하는 공간.

단순 리스트 구조 대신
분위기와 탐색 경험 자체를 중요하게 설계하였다.

---

### Workspace Runtime

IDE와 runtime window를 참고하여 만든 workspace 구조.

문서를 단순 markdown viewer로 보여주는 대신,
실행중인 workspace처럼 탐색 가능하도록 설계하였다.

---

### Manuscript Viewer

문서를 dashboard나 admin panel처럼 보여주지 않고,
실제 manuscript 혹은 기록 문서처럼 읽히도록 구성하였다.

typography와 whitespace를 중요하게 다루고 있다.

---

### Runtime Log System

PROJECT LOG와 DEV LOG는
실행중인 terminal process처럼 보이도록 구성하였다.

단순 code block이 아니라:

- boot sequence
- runtime session
- operational log

등의 분위기를 표현하는 방향으로 설계하였다.

---

## 지향하는 포트폴리오 방향

Luda Log는 결과만을 보여주는 사이트보다,
운영과 구조를 함께 기록하는 archive를 목표로 한다.

특히:

- 운영 중 발생한 문제
- 구조적인 의사결정
- runtime 설계
- UX 방향성
- 실제 사용 환경에서의 고민

등을 지속적으로 기록하고 정리하는 방향을 지향한다.

이 archive는 단순 포트폴리오를 넘어,
개발 과정 자체를 남기는 기록 시스템을 목표로 한다.
