<summary id="overview">

  <span className="wiki-fold-title">
    개요
  </span>

</summary>
<div markdown="1">

JumpingBattle 서비스의 규모가 증가함에 따라 전국 랭킹, 매장별 랭킹뿐만 아니라
맵, 난이도, 아이템 여부 등 다양한 조건에 따른 랭킹 조회 기능을 제공하게 되었습니다.

이 과정에서 단순히 검색 기능을 제공하는 것뿐만 아니라,
검색 결과를 어떤 기준으로 사용자에게 보여줄 것인가 역시 중요한 문제였습니다.

특히 본 서비스의 특성상 사용자는 다른 사람의 기록을 탐색하기보다는
자신의 기록과 순위를 확인하기 위해 검색 기능을 사용할 가능성이 높다고 판단하였습니다.

따라서 검색 결과의 정확성뿐만 아니라,
사용자가 원하는 정보를 얼마나 빠르게 찾을 수 있는가를 중요한 기준으로 삼아
정렬 정책을 설계하였습니다.

</div>


</details>

<summary id="initial-options">

  <span className="wiki-fold-title">
   초기 검토 방식
  </span>

</summary>
<div markdown="1">

초반에는, 검색의 정확도보다는 게임이라는 특성을 살리고자 난이도 등에 따른 가중치를 우선으로 두었습니다.
따라서 맵의 크기가 큰 순 난이도가 높은순 등을 기준으로 점수순 정렬을 기본으로 제공하였고,
매장 ㄱㄴㄷ순을 제공하여 본인의 정보에 대한 접근성 역시 높였습니다.

하지만 MVP 완성 이후 진행한 QA 과정에서
실제 사용자들의 검색 패턴을 관찰해보았습니다.

지인들을 대상으로 특정 닉네임의 기록을 찾아보도록 요청하였으며,
어떤 기준으로 결과를 탐색하는지 확인하였습니다.

그 결과 사용자들은 특정 난이도의 최고 점수를 확인하기보다는,
최근에 플레이한 기록이나 특정 매장에서의 기록을 찾는 경우가 많았습니다.

또한 동일한 닉네임에 대해 여러 검색 결과가 존재하는 상황에서는
점수만을 기준으로 정렬하는 것보다 사용자가 익숙한 매장명이나 최근 플레이 날짜를 기준으로 탐색하는 편이 훨씬 직관적이었습니다.

이에 따라 검색 결과의 기본 정렬 기준을
매장명 기준 정렬과 날짜 기준 정렬로 변경하게 되었습니다.

이를 통해 사용자는 자신이 원하는 기록을 보다 빠르게 찾을 수 있었으며,
검색 결과를 탐색하는 과정에서의 피로도 역시 줄일 수 있었습니다.

</div>

<summary id="final-strategy">

  <span className="wiki-fold-title">
    매장명 정렬 및 날짜순 정렬 채택 이유
  </span>

</summary>
<div markdown="1">

최종적으로는 매장명 기준 정렬과 날짜 기준 정렬을 기본 정책으로 채택하였습니다.

가장 큰 이유는 사용자의 검색 목적이 특정 랭킹의 우열을 확인하는 것보다,
자신의 기록을 빠르게 찾는 것에 가깝다고 판단하였기 때문입니다.

특히 동일한 닉네임으로 여러 기록이 존재하는 경우,
점수만을 기준으로 정렬할 경우 사용자가 원하는 결과를 찾기 위해
여러 페이지를 탐색해야 하는 상황이 발생할 수 있었습니다.

반면 매장명 기준 정렬은 사용자가 실제로 방문한 매장을 기준으로
결과를 탐색할 수 있도록 도와주었으며,
날짜 기준 정렬은 최근 플레이한 기록을 우선적으로 확인할 수 있도록 해주었습니다.

또한 대부분의 사용자는 자신의 최신 기록이나
최근 방문한 매장의 결과를 확인하는 경우가 많았기 때문에,
해당 정렬 방식이 실제 이용 패턴과도 잘 부합한다고 판단하였습니다.

결과적으로 본 서비스에서는 검색 결과의 정확성뿐만 아니라
사용자가 원하는 정보를 얼마나 빠르게 찾을 수 있는가를 우선적으로 고려하였으며,
이에 따라 매장명 및 날짜 기준 정렬을 기본 정책으로 채택하게 되었습니다.

</div>
