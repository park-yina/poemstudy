<summary id="entrance-system">

  <span className="wiki-fold-title">
    입구 시스템의 도입
  </span>

</summary>

<div markdown="1">

루다로타의 입구 시스템은
사용자가 archive 내부로 진입하기 이전,
분위기와 탐색 흐름을 전환하기 위해 설계되었다.

특히:

`사이드바 → 선반 위 도서 → 기도초`

순으로 탐색 흐름이 이어지도록 구성하였다.

해당 구조는 모두
단순 정보 분류보다,
현재 사용자가 어떤 archive에 접근하고 있는가를
직관적으로 전달하는 데에 초점을 두었다.

<details
  className="wiki-subfold"
  open
>

<summary id="book-ui">

도서 형태의 프로젝트 아카이브

</summary>

<div markdown="1">

초기 구조에서는
프로젝트를 단순 카드 단위로 분류하였다.

하지만 JumpingBattle과 같이
프로젝트 내부의 구조 변화와 운영 기록이 지속적으로 증가하는 경우,
하나의 시리즈 archive처럼 보이도록 구조를 변경하였다.

이를 통해:

- 프로젝트 흐름
- 구조 변화
- 운영 기록

등을 하나의 기록물처럼 탐색할 수 있도록 구성하였다.

</div>

</details>

<summary id="candle-ui">

기도초 형태의 카드 선택

</summary>

<div markdown="1">

사용자가 단순 버튼을 클릭하는 것이 아니라,

기도초 형태의 선택 구조를 도입하였다.

<DocsRef>

해당 구조 이전에는:

- 신전 형태의 입구
- 전체 카드 노출 방식

등 역시 시도되었으나,
현재 구조가 가장 탐색 흐름 유지에 적합하다고 판단하였다.

</DocsRef>

</div>

<summary id="card-reading">

  <span className="wiki-fold-title">
    카드 리딩 인터랙션
  </span>

</summary>

<div markdown="1">

LudaRota의 핵심 목표는
프로젝트를 단순 카드 목록이 아니라,
“해석 가능한 기록”처럼 느끼게 만드는 것이었다.

특히:

- 카드 포커싱
- 미세한 animation
- 카드별 서사 구조

등을 통해
사용자가 프로젝트를 읽는 것이 아니라,
하나의 기록을 해석하는 흐름을 목표로 하였다.

또한 각 프로젝트별 분위기와 runtime 특성을
카드 단계에서 먼저 전달할 수 있도록 설계하였다.

</div>

</details>

<summary id="card-decode">

  <span className="wiki-fold-title">
    카드 확장 및 Decode 구조
  </span>

</summary>

<div markdown="1">

일부 프로젝트는
단순 카드 하나만으로 설명하기 어려운 구조적 이슈를 포함하고 있었다.

특히:

- SSE 시스템 도입 과정
- CacheKey 설계 및 실패 경험
- Delta Payload 구조
- Runtime Synchronization

등은
실패 과정과 구조 선택 이유 모두 중요하였다.

따라서 특정 archive 내부에
별도의 decoding 및 확장 흐름을 추가하였다.

<details
  className="wiki-subfold"
  open

<summary id="subcard-system">

서브 카드 시스템 도입

</summary>

<div markdown="1">

Subcard 시스템은
하나의 프로젝트 내부에서
세부 구조와 실패 사례를 다시 탐색할 수 있도록 만들기 위해 도입되었다.

이는 단순 상세보기보다,
“기록 내부의 또 다른 기록”을 탐색하는 구조를 목표로 하였다.

특히:

- ranking 구조 변경
- cache invalidation
- partial update
- runtime state

등의 기록은
별도의 subcard로 분리하여 설명하였다.

</div>

</details>

</div>

</details>

  <span className="wiki-fold-title">
    p5.js 기반 Ambient Animation
  </span>

</summary>

<div markdown="1">

LudaRota의 animation은
단순 시각 효과보다,
archive 내부의 공간감과 정적인 분위기를 강화하는 데에 초점을 두었다.

특히:

- ambient particle
- mouse interaction
- archive dust
- runtime motion

등을 통해
사용자의 입력에 반응하는 archive 공간을 구성하였다.

또한 단순 CSS animation보다,
보다 유기적인 interaction 흐름을 구현하기 위해
p5.js 기반 구조를 일부 도입하였다.

  <span className="wiki-fold-title">
    Theme 기반 Tarot 구성
  </span>

</summary>

<div markdown="1">

theme는 단순 색상 변경이 아니라,
archive별 분위기와 탐색 흐름 자체를 구분하기 위한 구조였다.

특히:

- forbidden archive
- runtime overlay

등을 중심으로,
각 기록이 서로 다른 감각을 가지도록 설계하였다.

또한 동일한 archive ecosystem 안에서도,
theme에 따라 전혀 다른 탐색 경험을 제공할 수 있도록 구성하였다.

</div>

<summary id="navigation-fatigue">

  <span className="wiki-fold-title">
    탐색 피로도를 줄이기 위한 설계
  </span>

</summary>

<div markdown="1">

기존 wiki 기반 구조에서는
문서 depth가 깊어질수록
사용자의 탐색 피로도 역시 증가하는 문제가 존재하였다.

LudaRota에서는:

- overlay 기반 탐색
- 카드 포커싱 animation
- decoding 방식 탐색
- runtime 중심 흐름 유지

등을 통해
사용자가 현재 읽고 있는 흐름이 끊기지 않도록 설계하였다.

특히 단순 링크 이동보다,
“현재 archive 내부를 계속 탐색하는 감각”을 유지하는 데에 집중하였다.

</div>

</details>
