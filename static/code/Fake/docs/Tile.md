# Tile.md

## 도입 배경

초기 구조에서는 센서 입력, RGB 출력, 점수 상태 등을 각각 개별 장비 기준으로 관리하려 했다.

하지만 점핑배틀의 실제 게임 흐름은 단순 장비 제어보다,
"특정 위치의 상태가 어떻게 변하는가"에 더 가까웠다.

즉 게임의 핵심은:

- 어떤 블록이 SAFE 상태인지
- 어떤 블록이 SCORE 상태인지
- 어떤 블록이 눌렸는지
- 현재 어떤 상태를 화면과 LED에 반영해야 하는지

를 지속적으로 관리하는 것이었다.

이 과정에서 장비 중심 구조보다,
게임 상태 자체를 하나의 단위로 관리하는 방식이 더 적합하다고 판단했다.

---

## 기존 구조의 문제점

### 장비 단위 상태 관리의 한계

초기에는:

- SENSOR
- RGB
- SCORE
- PRESS

등을 각각 별개의 상태로 관리하려 했다.

하지만 실제 구현에서는 다음과 같은 문제가 발생했다.

- LED 출력과 게임 판정 로직이 분리됨
- 상태 변경 시 여러 장비 로직을 동시에 수정해야 함
- SAFE / UNSAFE 상태와 점수 상태가 서로 다른 위치에서 관리됨
- 장비 수가 늘어날수록 상태 동기화 복잡도가 증가
- 게임 룰 변경 시 전체 구조 영향 범위가 커짐

특히 점핑배틀은
"안전 영역이 계속 바뀌는 구조"이기 때문에,
개별 장비 기준 접근은 상태 흐름을 관리하기 어려웠다.

## Tile 기반 구조로의 전환

### 상태 중심 블록 관리

이후 게임의 최소 단위를 장비(Device)가 아닌 Tile로 재정의했다.

각 Tile은:

- SAFE
- UNSAFE
- SCORE
- PRESSED(구현미완)
- BLINK

등의 상태를 포함하는 구조로 변경했다.

예시:

```text
bit 0 = SAFE
bit 1 = UNSAFE
bit 2 = SCORE
bit 3 = PRESSED
bit 4 = BLINK
